# Shopify Liquid Rules (Theme Development)

## Summary
Authoritative rules for generating, validating, and maintaining **Shopify theme-scope Liquid** code. These rules enforce correctness, prevent hallucinated Liquid syntax, and ensure alignment with Shopify’s officially supported Liquid schema and theme architecture.

All Liquid generated by the agent must be compatible with:
- Shopify Online Store 2.0
- Theme Editor dynamic rendering
- Section-based templates
- B2B and retail storefront contexts

---

## Authoritative Schema Source
The single source of truth for Shopify **theme Liquid** objects, tags, and filters is:

```

vendor/theme-liquid-docs/

````

Specifically:
- `data/objects/*.json`
- `data/filters/*.json`
- `data/tags/*.json`

If a Liquid object, property, tag, or filter does **not** exist in this repository, it is considered **unsupported or unsafe**.

---

## Hard Rules (Must Always Be Followed)

### 1. No Invented Liquid
- Do NOT invent Liquid objects
- Do NOT invent object properties
- Do NOT invent tags or filters
- Do NOT assume undocumented behavior

If it is not defined in `theme-liquid-docs`, it must not be treated as guaranteed.

---

### 2. Schema Existence Does Not Guarantee Runtime Availability
Objects may exist in the schema but be `nil` at runtime.

All optional objects must be guarded defensively.

Example:
```liquid
{% if customer and customer.metafields %}
````

---

### 3. Mandatory Runtime Guards

The following objects must **always** be guarded before use:

* `customer`
* `cart`
* `customer.company`
* `customer.metafields`
* `request`

Unconditional access to these objects is prohibited.

---

### 4. No Business Logic Inference

The Liquid schema does **not** define:

* B2B eligibility
* Pricing rules
* Catalog assignment
* Market behavior
* Checkout logic

The agent must never infer business rules from schema alone.
All business logic must come from explicit instructions.

---

## B2B-Specific Liquid Rules

* Prefer `customer.company` and `customer.b2b?` when available
* Always guard B2B objects
* Metafields must be accessed using:

  ```liquid
  customer.metafields.<namespace>.<key>
  ```
* Never assume metafield existence
* Metaobject references must be accessed via documented fields only

---

## Template & Theme Architecture Rules

* Homepage templates: `index.*.json`
* Page templates: `page.*.json`
* Product templates: `product.*.json`
* Collection templates: `collection.*.json`
* Layouts must exist in `/layout/`
* Sections must exist in `/sections/`
* Snippets must exist in `/snippets/`

Missing layouts or sections may cause Shopify to silently hide templates.

---

## Preferred Patterns

* Prefer `{% render %}` over `{% include %}`
* Follow patterns used in Shopify’s **Dawn** theme
* Keep Liquid logic minimal
* Push behavior into sections and snippets
* Avoid complex logic in layouts

---

## Prohibited Patterns

* Using URL parameters (`?view=`) as a primary rendering mechanism
* Mixing retail and B2B logic without explicit instruction
* Referencing undocumented Liquid fields as guaranteed
* Embedding JavaScript logic directly in Liquid

---

## Fallback & Error Handling

If a Liquid reference is:

* Undocumented
* Ambiguous
* Context-dependent

The agent must:

* Ask for clarification **or**
* Generate guarded, defensive Liquid with explanation

Fabrication is not allowed.

---

If it is not guaranteed, it must be guarded or rejected.**
