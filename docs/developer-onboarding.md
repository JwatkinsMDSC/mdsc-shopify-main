## Why Docker?

### The Problem Docker Solves

Traditional Shopify theme development faces several challenges:

1. **Environment Inconsistency**
   - "Works on my machine" syndrome
   - Different Node/Ruby/npm versions across team members
   - Platform differences (macOS, Windows, Linux)

2. **Dependency Conflicts**
   - System-wide Node installations interfere
   - Ruby version conflicts
   - Shopify CLI compatibility issues

3. **Onboarding Friction**
   - New developers spend hours configuring environments
   - AI agents need reproducible, predictable setups
   - Documentation becomes outdated quickly

4. **Build Reproducibility**
   - Assets compiled differently on different machines
   - Hard to debug deployment issues
   - CI/CD pipelines don't match local development

### How Docker Solves It

Docker provides:

✅ **Isolated Environment**
- Self-contained with all dependencies
- No conflicts with system software
- Same environment for everyone

✅ **Reproducible Builds**
- Identical output across all machines
- Deterministic asset compilation
- Predictable deployments

✅ **Easy Onboarding**
- One command to start: `docker compose up`
- No manual installation of dependencies
- Automatic environment setup

✅ **Version Locked**
- Node 20 LTS guaranteed
- Ruby version controlled
- Shopify CLI version pinned

✅ **Multi-Store Ready**
- Deploy to multiple franchises from one codebase
- Consistent builds across all stores
- Global updates propagate reliably

## Development Philosophy

### Single Source of Truth

The MDS Global Theme Framework uses a **monorepo approach**:

```
One Repository → Many Stores
```

- All franchise stores share the same codebase
- Custom overrides per store (colors, logos, etc.)
- Global updates deployed to all stores simultaneously

### Build Pipeline

```
Source Code → Docker Build → Compiled Assets → Shopify Stores
     ↓              ↓                ↓                ↓
  Tailwind       Vite            global.css      Deployment
    CSS        Bundler          global.js         Script
```

### Technology Stack

- **Theme Base**: Taillour Boilerplate Theme
- **CSS Framework**: Tailwind CSS v4
- **Build Tool**: Vite 5
- **JavaScript**: ESM Modules + Web Components
- **Slider Library**: Swiper.js 11
- **Deployment**: Shopify CLI 3.x

## Getting Started

### Prerequisites

Before starting, ensure you have:

1. **Docker Desktop installed**
   - macOS: https://docs.docker.com/desktop/mac/install/
   - Windows: https://docs.docker.com/desktop/windows/install/
   - Linux: https://docs.docker.com/engine/install/

2. **Git installed**
   - Check: `git --version`
   - Install: https://git-scm.com/downloads

3. **Terminal access**
   - macOS: Terminal app
   - Windows: WSL2 + Ubuntu (strongly recommended)
   - Linux: Any terminal

4. **Shopify Partner Account** (for Shopify CLI)
   - Sign up: https://partners.shopify.com/

### Step-by-Step Setup

#### 1. Clone the Repository

```bash
git clone <repository-url>
cd mdsc-shopify-theme
```

#### 2. Configure Environment Variables

```bash
cp .env.example .env
```

Edit `.env` and set your Shopify store credentials:

```bash
SHOPIFY_STORE_URL=your-store.myshopify.com
SHOPIFY_CLI_THEME_ID=<your-theme-id>
```

**How to get your theme ID**:
```bash
# After Docker build, run:
./scripts/docker/dev.sh

# When prompted, authenticate with Shopify
# You'll see a list of themes with their IDs
```

#### 3. Build Docker Containers

```bash
docker compose build
```

**This will**:
- Download Node 20 base image (~500MB)
- Install Ruby and Shopify CLI
- Install npm dependencies
- Set up the development environment

**Time**: 5-10 minutes (first time only)

#### 4. Verify Installation

```bash
# Check Docker containers
docker compose ps

# Check helper scripts are executable
ls -la scripts/docker/
```

You should see:
- `dev.sh` (executable)
- `vite.sh` (executable)
- `build.sh` (executable)
- `deploy.sh` (executable)

## Understanding the Architecture

### Project Structure

```
mdsc-shopify-theme/
├── assets/                 # Compiled CSS/JS (generated by Vite)
├── config/                 # Theme settings + store configurations
│   ├── settings_data.json
│   ├── settings_schema.json
│   └── stores/            # Per-store overrides
│       ├── headquarters/
│       ├── miami/
│       └── ...
├── docs/                   # Documentation
│   ├── docker.md
│   ├── developer-onboarding.md
│   ├── deployment.md
│   └── multi-store.md
├── layout/                 # Shopify theme layouts
│   ├── theme.liquid
│   └── password.liquid
├── locales/                # Translations
├── scripts/                # Build and deployment scripts
│   ├── deploy.js           # Multi-store deployment
│   └── docker/             # Docker helper scripts
│       ├── dev.sh
│       ├── vite.sh
│       ├── build.sh
│       └── deploy.sh
├── sections/               # Shopify sections (44 from Taillour)
├── snippets/               # Reusable Liquid components
├── src/                    # Source code (pre-build)
│   ├── scripts/
│   │   ├── global.js       # Main entry point
│   │   ├── components/     # Web Components
│   │   └── core/           # Component/Section registries
│   └── styles/
│       └── tailwind.css    # Tailwind + MDS design tokens
├── templates/              # Shopify template files
├── Dockerfile              # Docker container definition
├── docker-compose.yml      # Docker services configuration
├── vite.config.js          # Vite build configuration
├── tailwind.config.js      # Tailwind configuration
└── package.json            # Node dependencies
```

### Key Files

#### **Dockerfile**
Defines the Docker container with Node 20, Ruby, Shopify CLI, and dependencies.

#### **docker-compose.yml**
Orchestrates Docker services:
- `node-dev`: Main development environment
- `theme-check`: Linting service

#### **vite.config.js**
Configures Vite to:
- Bundle `src/scripts/global.js` → `assets/global.js`
- Compile `src/styles/tailwind.css` → `assets/global.css`
- Minify assets for production
- Set up path aliases (@scripts, @styles, @components)

#### **tailwind.config.js**
Configures Tailwind CSS v4:
- Content sources (Liquid files, JS files)
- Custom MDS design tokens defined in `src/styles/tailwind.css`

#### **src/scripts/global.js**
Main JavaScript entry point:
- Imports all Web Components
- Initializes Component Registry
- Initializes Section Registry
- Sets up Shopify Section Rendering API handlers

#### **scripts/deploy.js**
Multi-store deployment script:
- Reads store configurations from `config/stores/`
- Deploys to single store or all stores
- Supports per-store overrides

## Development Workflows

### Workflow 1: Asset Development (CSS/JS)

**Goal**: Develop custom Tailwind styles or JavaScript components with hot reload.

```bash
# Terminal 1: Start Vite dev server
./scripts/docker/vite.sh

# Terminal 2: Make changes to files
# - src/styles/tailwind.css
# - src/scripts/**/*.js

# Vite automatically rebuilds on file save
# Check output in assets/global.css and assets/global.js
```

**Access**: http://localhost:3000

**When to use**:
- Adding new Tailwind utility classes
- Creating Web Components
- Debugging JavaScript issues
- Modifying design tokens

---

### Workflow 2: Theme Development (Liquid)

**Goal**: Develop Shopify theme sections, templates, and snippets with live preview.

```bash
# Terminal 1: Start Shopify dev server
./scripts/docker/dev.sh

# Follow authentication prompts
# - Open URL in browser
# - Enter verification code
# - Grant permissions

# Terminal 2: Make changes to Liquid files
# - sections/*.liquid
# - templates/*.json
# - snippets/*.liquid

# Shopify CLI auto-reloads theme on save
```

**Access**: Your Shopify store URL (provided by CLI)

**When to use**:
- Creating new sections
- Modifying templates
- Testing with real Shopify data
- Debugging Liquid logic

---

### Workflow 3: Full-Stack Development

**Goal**: Work on both assets and theme files simultaneously.

```bash
# Terminal 1: Vite dev server
./scripts/docker/vite.sh

# Terminal 2: Shopify dev server
./scripts/docker/dev.sh

# Terminal 3: Make changes to any files
# Both servers auto-reload
```

**When to use**:
- Building new features that span CSS, JS, and Liquid
- Integration work
- End-to-end testing

---

### Workflow 4: Production Deployment

**Goal**: Build and deploy production-ready theme to Shopify stores.

```bash
# Step 1: Build production assets
./scripts/docker/build.sh

# Step 2: Test locally (optional)
./scripts/docker/dev.sh

# Step 3: Deploy to staging store
./scripts/docker/deploy.sh --store=staging

# Step 4: Test on staging store
# Visit: https://staging-store.myshopify.com

# Step 5: Deploy to production store
./scripts/docker/deploy.sh --store=headquarters

# Step 6: Deploy to all franchise stores
./scripts/docker/deploy.sh --all
```

## Best Practices

### 1. Always Work in Docker

❌ **Don't**: Install Node/Ruby/npm on your host machine for this project

✅ **Do**: Use Docker for all development

**Why**: Ensures consistency and avoids conflicts.

---

### 2. Use Helper Scripts

❌ **Don't**: Run long Docker commands manually

```bash
docker compose run --rm --service-ports node-dev npm run build
```

✅ **Do**: Use provided helper scripts

```bash
./scripts/docker/build.sh
```

**Why**: Scripts include error handling, logging, and validation.

---

### 3. Build Before Deploying

❌ **Don't**: Deploy without building

```bash
./scripts/docker/deploy.sh --store=production --no-build
```

✅ **Do**: Build first

```bash
./scripts/docker/build.sh
./scripts/docker/deploy.sh --store=production
```

**Why**: Ensures latest assets are included in deployment.

---

### 4. Test Locally First

❌ **Don't**: Deploy directly to production

```bash
./scripts/docker/deploy.sh --store=headquarters
```

✅ **Do**: Test on staging first

```bash
./scripts/docker/deploy.sh --store=staging
# Test thoroughly
./scripts/docker/deploy.sh --store=headquarters
```

**Why**: Catch issues before they affect customers.

---

### 5. Keep Dependencies Updated

```bash
# Update npm dependencies
docker compose run --rm node-dev npm update

# Rebuild container
docker compose build
```

**Frequency**: Monthly or when security updates are released.

---

### 6. Use Version Control

❌ **Don't**: Commit generated files

- `assets/global.css`
- `assets/global.js`
- `node_modules/`

✅ **Do**: Commit source files only

- `src/**/*`
- `sections/**/*`
- `templates/**/*`

These files are already in `.gitignore`.

## Troubleshooting Common Issues

### Issue: Docker Build Fails

**Symptoms**: Errors during `docker compose build`

**Solutions**:

1. **Check Docker is running**
   ```bash
   docker ps
   ```

2. **Clean rebuild**
   ```bash
   docker compose down
   docker compose build --no-cache
   ```

3. **Check disk space**
   ```bash
   df -h
   ```

---

### Issue: Port Already in Use

**Symptoms**: `Bind for 0.0.0.0:3000 failed`

**Solution**:

```bash
# Find process using port
lsof -i :3000

# Kill process
kill -9 <PID>

# Restart Docker service
./scripts/docker/vite.sh
```

---

### Issue: Changes Not Reflecting

**Symptoms**: File changes don't trigger rebuilds

**Solutions**:

1. **Verify file is saved**
2. **Check Docker volume mount**
   ```bash
   docker compose run --rm node-dev ls -la /workspace
   ```
3. **Restart service**
   ```bash
   # Ctrl+C to stop
   ./scripts/docker/vite.sh
   ```

---

### Issue: Shopify CLI Authentication Loop

**Symptoms**: Repeatedly asked to authenticate

**Solution**:

```bash
# Remove cached credentials
rm -rf ~/.shopify

# Authenticate again
./scripts/docker/dev.sh
```
