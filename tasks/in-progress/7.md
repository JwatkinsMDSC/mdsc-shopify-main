## 3️⃣ Big strategic questions you asked

### ❓ Should we use `<component-name>` tags instead of data attributes?

**Short answer:**
❌ No, not right now.

**Long answer (important):**

You are building a **Shopify theme**, not a web component library.

Using custom tags would:

* require stricter DOM guarantees
* complicate Liquid rendering
* confuse non-JS contributors
* create hydration edge cases
* slow you down right now

Your current pattern:

* semantic HTML
* `data-*` attributes
* JS controllers attaching behavior

is **exactly correct** for:

* Shopify
* Liquid
* theme editor reloads
* partial re-renders

👉 **Recommendation:**
Stick with attributes. Revisit custom elements **after launch**, if ever.

### Menu Drawer with drag gestures (Item 3)

You are thinking about this correctly.

Key requirements you should enforce in the task:

* Pointer events, not mouse/touch split

* Backdrop opacity tied to drag percentage

* Velocity threshold for dismiss

**Important:**
This drawer must support **stacking**, not just open/close.
